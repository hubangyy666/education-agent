# RAG 知识库搜集与自动入库规则（Codex）

> 适用于 AI 数据标注岗位培训智能体。  
> 目标：由 Codex 搜集可信资料，AI 自动判断知识质量，程序自动完成 Embedding 与入库。  
> 不设置人工审核环节，但必须通过来源校验、AI 质量审核和一致性校验后才能进入正式 RAG。

---

## 1. 知识分类

知识分为两类。

### 1.1 通用知识 `GENERAL`

不属于某一个具体能力，但与 AI 数据标注岗位直接相关，例如：

- 数据标注是什么
- Ground Truth
- Annotation / Label
- 标注任务基本流程
- 数据质检基本概念
- 审核、返修、交付
- 常见标注任务类型

格式：

```json
{
  "scope": "GENERAL",
  "ability_id": null,
  "skill_id": null
}
```

### 1.2 能力知识 `ABILITY`

按 A1～A10 分类：

```text
A1 标注基础认知
A2 标注规范理解
A3 分类与属性判断
A4 目标检测与定位
A5 精细分割
A6 工业缺陷识别
A7 复杂视觉场景
A8 文本与语义标注
A9 AI协同与质量审核
A10 综合项目交付
```

优先继续细分到 `skill_id`。

---

# 2. 来源限制

## S 级：优先采用

1. 官方技术文档
2. 官方数据集说明
3. 标准组织公开资料
4. 大学 / 研究机构公开资料
5. 正式学术论文

## A 级：允许采用

1. 主流开源标注工具官方文档
2. 主流 AI / 数据平台官方技术文档
3. 有明确作者、来源和技术依据的高质量技术文章

## B 级：仅补充使用

只有 S/A 级资料无法覆盖时才允许使用。

---

# 3. 默认禁止来源

以下内容不得作为正式知识库主要依据：

- CSDN 随机博客
- 知乎普通回答
- 百度知道
- 个人公众号转载
- 营销软文
- 无作者、无出处文章
- 无法追溯原始来源的二次转载
- 付费课程内部内容
- Brilliant 等商业平台付费内容
- 需要绕过登录、权限或付费墙访问的内容
- 来源或使用权限明显不清晰的资料
- 无可信来源支撑的 AI 自动生成内容

原则：

> 能找到原始来源，就不要使用二手转载。

# 4. Codex 搜集流程

固定流程：

```text
确定 GENERAL / A1～A10
        ↓
生成搜索关键词
        ↓
搜索可信来源
        ↓
来源过滤
        ↓
提取事实
        ↓
整理知识单元
        ↓
AI 质量审核
        ↓
AI 一致性审核
        ↓
通过？
   ├─ 否 → 丢弃或重新整理
   └─ 是
        ↓
自动 Embedding
        ↓
PostgreSQL + pgvector
```

不需要人工审核。

---

# 5. 每个来源必须记录

```json
{
  "source_name": "",
  "source_url": "",
  "source_type": "",
  "authority_level": "S|A|B",
  "license": "",
  "access_date": "",
  "notes": ""
}
```

所有入库知识必须可追溯来源。

---

# 6. 知识单元规则

不要把整篇网页直接塞进向量库。

必须：

```text
阅读来源
→ 提取事实
→ 重新整理
→ 形成独立知识单元
```

每条知识只解决一个问题

---

# 9. 内容要求

每条 `content` 建议：

```text
100～400 中文字
```

要求：

- 独立可理解
- 表达准确
- 不依赖网页上下文
- 不大段复制原文
- 不加入来源没有支持的结论
- 使用岗位语言
- 专业术语首次出现时可简短解释

---

# 10. AI 自动审核规则

每条候选知识必须经过单独的 AI Review。

必须评估：

```text
source_reliability
来源是否可信

factual_consistency
内容是否与来源一致

scope_relevance
是否真的属于 AI 数据标注岗位

clarity
是否适合作为独立 RAG 知识单元

duplication_risk
是否与现有知识高度重复

conflict_detected
是否与已有高权威知识冲突
```

建议所有分数范围：

```text
0.0 ～ 1.0
```

---

# 11. 自动通过阈值

建议：

```text
source_reliability >= 0.85
factual_consistency >= 0.90
scope_relevance >= 0.85
clarity >= 0.80
final_score >= 0.86
conflict_detected = false
```

满足全部条件：

```text
decision = approved
```

自动入库。

如果内容基本正确但表达不适合：

```text
decision = rewrite
```

由 AI 重新整理，再重新审核一次。

如果来源弱、事实不确定或明显冲突：

```text
decision = rejected
```

禁止入库。

---

# 12. final_score 建议

可以按：

```text
来源可信度       30%
事实一致性       30%
岗位相关性       20%
知识表达质量     15%
重复风险          5%
```

例如：

```text
final_score =
source_reliability * 0.30
+ factual_consistency * 0.30
+ scope_relevance * 0.20
+ clarity * 0.15
+ (1 - duplication_risk) * 0.05
```

---

# 13. 双模型 / 双阶段审核

为了避免“生成知识的 AI 自己给自己打满分”，推荐使用两阶段审核：

```text
模型 A
→ 搜集、提取、整理知识

模型 B
→ 独立审核知识
```

如果暂时只使用一个模型，也必须分两次独立调用：

```text
Call 1：生成知识

Call 2：只看来源 + 候选知识进行审核
```

第二次调用不得直接复用第一次生成理由。

（这两阶段审核是你来完成，而不是程序或外部ai来完成）

---

# 14. 冲突处理

如果发现多个高可信来源之间存在冲突：

```text
conflict_detected = true
decision = rejected
```

默认不自动合并。

如果是：

```text
项目规则 vs 通用规则
```

则允许：

```text
project_rule > general rule
```

但必须绑定对应项目范围，禁止污染 GENERAL。

---

# 15. 去重

入库前必须进行：

```text
标题相似度
+
Embedding 相似度
+
关键词重合
```

如果与已有知识高度重复：

```text
similarity >= 0.92
```

默认不新增。

优先保留：

```text
更高权威来源
>
事实更完整
>
版本更新
```

---

# 16. 自动入库条件

只有：

```text
ai_review.decision = approved
```

才允许进入：

```text
Embedding
→ PostgreSQL
→ pgvector
```

`rewrite`：

```text
重新整理
→ 再审核
```

`rejected`：

```text
记录日志
→ 不入库
```

---

# 17. 入库程序

推荐：

```text
scripts/import_knowledge.py
```

执行流程：

```text
读取候选知识
    ↓
检查 AI Review
    ↓
只处理 approved
    ↓
字段校验
    ↓
去重
    ↓
Embedding
    ↓
写 PostgreSQL
    ↓
写 pgvector
    ↓
记录来源与审核信息
```

# 19. 检索层级

AI Tutor 后续检索时：

```text
当前项目 project_rule
>
当前 skill_id
>
当前 ability_id
>
GENERAL
```

例如：

```text
用户当前：A4-S3

检索：
A4-S3
→ A4
→ GENERAL
```

---

# 20. Codex 必须遵守

1. GENERAL 和 A1～A10 必须明确分类；

2. 优先 S/A 级来源；

3. 不使用付费、受限、来源不明内容；

4. 不直接复制整篇网页；

5. 一条知识只解决一个核心问题；

6. 所有知识必须保留 source_url；

7. 搜集模型和审核模型必须逻辑分离；

8. 未通过 AI Review 的知识禁止入库；

9. 有明显来源冲突的知识禁止自动入库；

10. 高重复知识不重复写入；

11. AI 自动审核失败时宁可丢弃，不要强行入库；

12. 正式入库由程序完成，而不是 Codex 直接操作数据库。

    (这里说的ai审核也是你来审核)

---

# 21. 一句话规则

> **Codex 负责“搜索可信来源 + 整理候选知识”，独立 AI Review 负责“自动审核”，程序负责“去重 + Embedding + 自动入库”；不经过人工审核，但任何知识必须通过严格的来源、事实、一致性和质量阈值。**
>
> 知识库搜集只有这一次，尽可能搜集的全面。
